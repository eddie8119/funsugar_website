# SitePhoto｜拍攝須知與服務約定：雙 Tab 改版執行計畫

範圍：`/sitephoto/term-of-service`

## 1. 目標與決策

將既有單一長篇「拍攝須知與服務約定」改為兩個清楚切換的內容狀態：

- **公益攝影**（預設 Tab）：委託人直接捐款給公益機構，SitePhoto **完全不收取任何攝影相關費用**。明確界定場地準備責任、服務範圍、現場不符合拍攝條件時的處理方式。
- **一般付費攝影**：依雙方確認的報價、交付範圍及付款條件執行。保留合理的加購／額外修圖約定，但必須事前報價與同意。

**核心原則：公益案不提供「加價解決」的選項。** 超出公益服務範圍的整理、佈置、複雜修圖或額外拍攝需求，應由委託人自行處理、調整需求，或經雙方另行協商是否改為獨立商業委託；不得在已確認的公益案件中臨時加收費用。

## 2. 資訊架構與畫面

### 2.1 頁面佈局

1. 頁面標題：**拍攝須知與服務約定**。
2. 簡短導言：「請依照委託類型查看對應說明，申請前先確認拍攝條件與交付方式。」
3. 兩個分段式 Tab：`公益攝影`｜`一般付費攝影`。
4. 切換後顯示該類型完整條款，不把兩種收費制度混在同一段。
5. 頁尾 CTA：`返回 SitePhoto`、`申請攝影委託`。
6. 延續既有黑／白／黃品牌視覺；保留相機插畫，但縮減大面積留白，讓條款在桌面與手機都易讀。

### 2.2 Tab 互動

- 預設選取「公益攝影」，因為它是 SitePhoto 主打計畫。
- 點擊 Tab 只切換內容，不重新載入頁面。
- 以 URL query 保留狀態：`/sitephoto/term-of-service?type=charity`、`?type=paid`。重新整理或分享連結仍能開啟正確類型。
- 若 query 無效，回退公益 Tab。
- 切換後標題與內容保持語意正確；手機版 Tab 應能清楚點選。
- Tab 應使用真正的 `<button>`、`role="tablist"`、`role="tab"`、`aria-selected`、`aria-controls`，對應 `tabpanel`；提供鍵盤操作及可見焦點樣式。
- **SEO：** 單一 URL 以整頁共用的「拍攝須知與服務約定」為 Title/Description；兩個 Tab 的內容都應可被 SSR/靜態 HTML 讀取，不能僅在客戶端點擊後才從遠端載入。若目前頁面是靜態產生，需確認不會因 `v-if` 讓非預設 Tab 內容完全缺席於預渲染 HTML；可考慮兩個 panel 均渲染，透過 `hidden` 控制顯示。

## 4. 公益攝影 Tab：建議正式文案

> 以下為網站文案草案。正式上線前應核對實際服務能力與約定，尤其取消、改期及履約責任。

### 4.1 計畫與費用

**公益攝影完全不收取攝影服務費。** 委託人經 SitePhoto 確認名額及拍攝日期後，依方案將捐款**直接捐給公益機構**，SitePhoto 不經手捐款，也不向委託人收取拍攝、場地整理或額外修圖費用。

請先提出申請，**確認可以承接後再捐款**；自行提前捐款不代表已取得拍攝名額。

### 4.2 拍攝前，請先完成現場準備

為確保照片能忠實呈現完工品質，**委託人須在拍攝開始前完成下列事項**：

1. **空間已完工且完成清潔：** 無持續施工、油漆、粉塵、工程垃圾或大量待清理物品。
2. **家具與軟裝已就位：** 家具、燈具、窗簾、掛畫、植栽及其他預計入鏡的物件均已安排完成。
3. **雜物與線材已整理：** 移除紙箱、清潔工具、私人雜物及不希望入鏡的物品；整理外露線材。
4. **易反光處已清潔：** 鏡面、玻璃、龍頭、面盆等請先擦拭乾淨。
5. **現場可正常進出與拍攝：** 事先取得屋主同意，完成管委會、門禁、停車或進場協調；拍攝現場須安全、可用電且有合理作業空間。

**攝影師不負責現場清潔、搬運家具、大型軟裝佈置或代替委託人完成工程收尾。** 拍攝時可因構圖需要，酌情微調小型物件，但不構成整理或佈置服務。

### 4.3 現場未達拍攝條件時

若抵達後發現仍在施工、未完成清潔、物件大量堆置、無法安全進場，或必須花費大量時間整理才能拍攝，SitePhoto 得**暫停或不開始拍攝**，並說明原因。

雙方將依現場情況討論是否能在原訂時間內改善，或另行協調可安排的週末場次。**改期須以實際空檔為準，無法保證立即提供新日期。**

如因委託人未完成事前告知的必要準備，導致無法拍攝，SitePhoto 不負責代為整理場地，也不承諾額外補拍。若因 SitePhoto 自身原因無法履行，應主動提出合理的改期或其他補救方案，不得逕以本條免除責任。

### 4.4 精修與交付

包含空間水平／垂直與透視校正、曝光與色彩調整，以及合理範圍內的小型雜物修飾。**不包含大型物件移除、空間重建、複雜影像合成、材質更換或其他高難度修圖。**

公益攝影不提供付費追加修圖；超出範圍的要求可以婉拒。交付張數依已確認的公益方案，交付時間依雙方書面確認的時程辦理。

### 4.5 改期、取消與捐款

拍攝採週末預約制，服務範圍限台北市。若需改期，請儘早通知；新日期依可用場次另行確認。

捐款由委託人直接支付公益機構，**SitePhoto 無法代為退款**。因此請務必等候名額與日期確認後再捐款。若捐款後發生無法完成拍攝的情況，雙方應依原因及已完成的準備協商合理處理方式；如涉及 SitePhoto 可歸責的未履行，須提供適當補救，不可單方面將全部風險轉嫁委託人。

### 4.6 作品公開與隱私

請於申請時告知是否涉及屋主隱私、未公開的設計案或其他展示限制。拍攝作品能否用於 SitePhoto 官網、社群及作品集，須依事前取得的授權與雙方約定辦理；**不得將公益攝影視為自動取得無限制公開權利**。

## 5. 一般付費攝影 Tab：建議正式文案

### 5.1 服務範圍與報價

依案場坪數、拍攝內容、交付張數、時程及特殊需求個別報價。拍攝日期、付款方式及交付條件以雙方書面確認內容為準。

### 5.2 場地準備與現場配合

委託人須於拍攝前完成清潔、工程收尾、家具軟裝定位、雜物整理及必要的進場協調。攝影師可微調小型物件，但不包含大型家具搬運、全場清潔或專業軟裝佈置，除非已另行明確約定。

### 5.3 額外修圖

基本精修包含透視、曝光、色彩與小範圍瑕疵處理。大型物件移除、複雜合成或超出約定範圍的需求，應先評估並提供報價，**取得委託人同意後才執行**。

### 5.4 現場延誤、改期與取消

如現場未達拍攝條件、無法進場或須長時間等待，依事前確認的服務條件討論等待、改期或其他安排。取消費、改期費、訂金及退款方式應在報價／確認委託時明列，**不得事後臨時新增**。

### 5.5 交付與作品使用

選片、精修、交付張數、交付日期及照片使用授權，依個別委託內容確認。若涉及屋主隱私或不可公開的設計案，請在拍攝前告知。

## 6. 申請流程同步調整（避免只改條款頁）

### 6.1 Landing Page

- 在兩種方案／申請表單附近放置「查看拍攝須知與服務約定」連結。
- 公益攝影連到 `/sitephoto/term-of-service?type=charity`。

### 6.2 申請表單

- 依委託類型顯示對應條款連結。
- 新增必勾選確認：**「我已閱讀並了解對應的拍攝須知與服務約定。」**

- 勾選狀態應隨 Email 申請內容一併送出，以便留存申請時的確認紀錄。若要作為正式契約證據，仍建議於接受案件時另以 Email 書面確認條款版本及個別約定。

### 6.3 確認委託 Email

至少列出：委託類型、地址／拍攝區域、日期時段、方案與交付張數、場地準備責任、特殊需求、作品公開約定、取消改期方式、適用條款版本。公益案需明確註記「SitePhoto 不收費；捐款直接交付公益機構」。

## 7. Nuxt 2 實作方案

> 實際元件與檔案路徑須以目前完整專案為準；以下為建議架構，不假設既有元件名稱。

### 7.1 檔案建議

```text
pages/sitephoto/term-of-service.vue   # 保留現有路由，新增 Tab 狀態
components/sitephoto/TermsTabs.vue    # 可選：Tab 導覽與可存取性
components/sitephoto/CharityTerms.vue # 公益條款
components/sitephoto/PaidTerms.vue    # 付費條款
```

若現有頁面不複雜，可只保留單一 page 元件，避免過度拆分。

### 7.2 狀態與網址

- Nuxt 2 使用 Options API 的 `data`、`computed`、`watch` 或現有專案既定寫法；不要直接複製 Nuxt 3 的 `useSeoMeta`。
- 初始狀態依 `this.$route.query.type` 決定，預設 `charity`。
- Tab 切換時透過 `this.$router.replace({ query: { ...this.$route.query, type } })` 更新網址，避免產生過多瀏覽器歷史紀錄。
- 當 URL query 由瀏覽器導覽變動時，Tab 也需同步。
- 切換後可維持焦點於被選取的 Tab；支援左右方向鍵切換。

### 7.3 SEO 與語意

- `head()` 設定獨立 Title、Description、Canonical（不含 query）。
- 主標題使用單一 `h1`，各條款主題使用 `h2`／`h3`。
- 不因切換 Tab 而產生兩個不同 Canonical URL；`?type=paid` 是使用者介面狀態，不是獨立 SEO 頁。
- 確認兩套條款文字在預渲染 HTML 中可取得，且隱藏內容不造成重複的視覺呈現。

## 9. 建議執行順序

1. **P0｜確認政策**：定稿公益案「現場不符合條件」的判定、改期與補救方式；確認交付時程與作品授權。
2. **P1｜改造條款頁**：新增雙 Tab、各自內容、query 同步與手機版樣式。
3. **P1｜串接申請入口**：依委託類型連到對應 Tab，加入必要確認勾選。
4. **P2｜同步 FAQ 與通知 Email**：避免網站不同位置說法衝突。
5. **P2｜QA 與上線**：測試桌面／手機、靜態部署、SEO 及寄信。

## 10. 上線前需決策的三個問題

1. **現場未準備好時的處理門檻**：是否允許現場短時間自行整理？最多等待多久？建議不寫死時間，先以「不影響原訂拍攝品質與時段」判斷，再逐案書面確認。
2. **公益案已捐款但未完成拍攝**：委託人原因與 SitePhoto 原因的改期／補救方案要區分，尤其攝影師無法履行時的處理方式。
3. **作品授權**：公益案是否需要取得作品集展示同意？建議獨立勾選授權，不把公開展示視為無條件交換。
